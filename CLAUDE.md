# Tic Tac Chaos: project notes

Tic-tac-toe where every square is a mini-game. Mobile-first web game on GitHub Pages, with Firebase (Auth, Realtime Database, Cloud Functions) for online play.

## Architecture
Plain ES modules, no build step: GitHub Pages serves the files as they are.

- `index.html`: the shell (meta tags, `#app`, `src/ui/fonts.css`, `src/ui/styles.css`, `src/main.js` as a module).
- `src/main.js`: the entry. Loads every game's `view.js` (by the registry), registers the listeners in a fixed order, renders the sounds, boots.
- `src/core/`: the engine, pure (no page, no clock, no `Math.random`; every random choice from an rng passed in). `board.js` main board, turn flow, win and draw; `match.js` setup and new matches; `minis.js` a square's mini-game through the registry; `timer.js` one deadline a turn, playback timings; `random.js` seeded randomness; `ai.js` the computer on the main board (three levels: Easy, Normal, Hard; `cpuMove(state, rng, style, opts)`, opts.level/clock/budget); `aiw.js` the levels and the Hard weights (`config/ai`, tuned by `npm run tune-ai`); `mc.js` Hard's square choice by Monte Carlo playouts; `chaos.js` Super Chaos (simultaneous rounds vs the computer, or a friend in a room); `scgame.js` a Super Chaos match from Find Match as the server runs it; `records.js` online match records (secrets kept apart); `games.js` release control; `config.js` tunable settings; `replay.js` a move's replay log (its shape and limits; the server keeps it on the move's entry); `tune.js` every game's settings (`config/tune/<type>`: `tuneLive(type)` when dealing a square, `tune(mini)` after; a square keeps its values in `mini.tune`); `stats.js` (also `topOpponents`/`oppTally`: a profile's Top opponents, from the server's `oppStats` tally), `util.js`. `engine.js` gathers the engine's public names (the server and tests use it as `E`).
- `src/games/<game>/`: one folder per mini-game (50, including the retired Dice race and Hexapawn).
  - `rules.js`: pure logic, shared with the server. Hooks the core calls: `create`, `apply`, `publicView`, `randomMove`, `moveFlash`, `secret`, `hide`, `flashMs`; Super Chaos's `scCreate`, `scRound` (a draw both moves that round share), `scFork`, `scApply`, `scAfter`, `scMerge` where a game needs them.
  - `ai.js`: `needs` (moves still needed) and `best` (the computer's move; `ctx.level` 'easy' | 'normal' | 'hard' and `ctx.until`, the ms a Hard search may still spend, null for a fixed amount of work: Hard searches or plays by expected value there, Normal is never changed by it).
  - `meta.js`: `info` (name, hint), `category` (its label in the "?" explainer), `target` ('shared', 'own' or 'course': the header's icon; `scTarget` where Super Chaos differs), `explainer` ({ name, play, win } for the "?"), `icon`, `release` ('admin' or 'released'), `superChaos` (dealt in Super Chaos), `scOnly` (never in a normal match) and `scExplainer` where its rules differ there, default settings (`*_DEFAULTS`), `TUNE` (its settings for the admin's Mini-game Settings: `{ k, label, def, min, max, step, group }`; `{k}` in an explainer shows the value).
  - `view.js`: `screen`, `miniature`, `moveText`, `sounds`, `actions` (its own `data-act` controls), `replay` (hooks for the shared replay: `input`, `synth`) where it keeps a draft, its drawing, animations and input.
  - A hook a game lacks falls back to the core's default. Wordle and Hangman keep their word lists in `words.js`.
- `src/games/shared/`: what a family shares (runner, attention, finger, physics with `physics-sim.js` on Matter.js, cards, lines, placement). A game's `rules.js` re-exports the family's hooks. Pinball's tables live in `physics-sim.js` (`PIN_LAYOUTS`, the lower table, `pinTable`, `pinLayoutCheck`): a square deals a layout and seven of its spots (`pinball/rules.js` `pinDeal`), and `tests/games/pinball.test.js` holds every layout to the layout check (an overlap fails `npm test`, so the deploys).
- `src/games/index.js`: the registry, one line per game (rules, AI, meta) in menu order, retired games last. `TYPES`, `TEST_TYPES` (from `meta.release`), `OLD_TYPES` and `INFO` come from it. The core dispatches with `rulesOf(type).apply(...)`, `aiOf(type).best(...)`, `viewOf(type).screen(...)`.
- `src/ui/`: `app.js` (state, timings, shared helpers), `render.js`, `board.js`, `mini.js`, `turnbar.js`, `turns.js` (computer's turn, result card), `replay.js` (opponent replays: an opponent's logged inputs played through the view, the Skip button; this phone's inputs logged for its moves), `chaos.js` (Super Chaos's round clock, recap and the 2x replay pop-up), `clock.js`, `input.js` (click handler; game controls go to the view's `actions`), `think.js` + `ai.worker.js` (the Hard computer's move worked out in a worker within its budget), `screens/`, and the shared components: `attention.js`, `runner.js`, `finger.js` (frameworks), `physics.js` (helpers), `progress.js` (bars, tallies), `explainer.js` (the "?" pop-up), `cards.js`, `track.js`, `keyboard.js`, `art.js`, `fx.js`. `sandbox.js` is the admin's Test play (`?sandbox=<game>&cfg=…`: one mini-game with the editor's unsaved settings, nothing saved). `config.js` holds the storage key and switches (`RATINGS_ENABLED`). `debug.js` puts the page's names on `window` for the browser tests and the console.
- `src/audio/sound.js`: the single sound manager. `SND.ensure` checks the context before every sound and replaces one that is not running (or whose clock stopped); the "Tap to restore sound" chip shows while audio is down; state changes go to the device and match logs (devlog `audio`).
- `src/net/`: `connect.js` (Firebase config, SDK, server time), `room.js` (friend games, presence, playback of the opponent's moves), `chaos.js` (Super Chaos in a friend room: moves sent in, the round settled on the record, recaps), `moves.js`, `matchmaking.js` (Find Match), `accounts.js`, `releases.js`, `reactions.js`, `tracking.js`.
- Client and server share `rules.js`: `functions/index.js` requires `src/core/engine.js` (Node 22 loads ES modules with `require`). `scripts/sync-functions.js` copies `src/core` and `src/games` (no views) and `trivia.json` into `functions/` before every deploy (firebase.json predeploy) and every emulator run.
- Load-time rule: a module must not use another module's value while loading if the two import each other (only inside functions). Keys and switches read at load live in `ui/config.js` and `core/config.js`.
- `admin.html` + `playtest.js`: the admin dashboard: a menu of section tiles, each a page (`#overview`, `#players`, `#playtest`, `#matches`, `#settings` and `#settings/<type>`, `#bots`, `#releases`, `#stats`). Mini-game Settings reads each game's `meta.js` (`TUNE`) and `core/tune.js` by import; the older tuning cards keep their own copies of a few defaults (`tests/core/admin-sync.test.js` checks them).
- Match logs (`functions/matchLogRules.js`): every online and Super Chaos match keeps a compact event log (`matchLogs/{key}`, summary in `matchLogIndex`), written by the server where it can (Find Match moves, the friend rooms' record, presence) and by the phone through `devlog` (`error`, `mlog`, `report`: `net/tracking.js`); deleted 30 days after the last event. The admin's Match inspector lists them (reported first), shows a timeline and exports one as JSON. The in-game menu's "Report a problem" (`ui/report.js`) flags the match.
- The computer: `scripts/ai-arena.js` plays the computer against itself over worker threads (`npm run tune-ai` tunes Hard's weights by self-play and saves them to `config/ai` with `--save`; never run automatically; `npm run sim -- levels` reports Hard against Normal). The bots' level is the admin's (`admin/config/bots/level`, Bot Settings).
- Tests: `npm test` runs `tests/games/<game>.test.js`, `tests/shared/`, `tests/core/`, `tests/server/` and `tests/page.test.js` (about 10 s); one game alone: `node --test tests/games/<game>.test.js`. `npm run sim -- <name>` runs a slow simulation in `tests/sim/` (`npm run sim` lists them). `npm run test:emulators` runs the server on the Firebase Emulator Suite (needs Java). `tests/server/chaos-online.test.js` (in `npm test`) plays a friend-room Super Chaos match with two SDK clients on the database emulator (the jar in firebase-tools' cache, `firebase setup:emulators:database`; skipped, and says so, without it or Java).
- Deploy: `./deploy.sh "message"` commits, pushes `main` and deploys only what changed since the live version (git diff): the site through `pages.yml`, functions and/or rules through `firebase.yml` (tests first). `DEPLOY_REMOTE` picks the remote (the live repository is Tiger-tac-toe).

## Adding a mini-game
Create src/games/<name>/ with rules.js, view.js, ai.js and meta.js, and register it. Every game needs: its settings (`TUNE` in meta.js, every tunable value), an explainer (in the format below), AI with a Hard form where the game has choices (`best` reads `ctx.level === 'hard'` and keeps to `ctx.until`), a miniature for the main board, AI, a timeout rule, animations, sounds, stats tracking, a default release status of Admin only, a category in its meta.js (`category`: 'luck', 'skill' or 'brain': shown as "More luck" etc. at the top of its "?" explainer; the Mini-games checklist is one alphabetical list), and a target kind (`target`: 'shared', 'own' or 'course').

## Standing rules (apply to every change)
- Layout never shifts. Reserve fixed space for status, result text and buttons; no board moves when text appears or disappears. Text never overlaps: a move's result text (live or in a replay, normal and Super Chaos) goes in its game's reserved result area and never covers other text or the game's drawing; text that swaps in over time (`.tu`/`.tf`/`.tu2`) shows one line at a time.
- Animations and sounds fire exactly once, from the move event that caused them, never from rendering or re-rendering. The main board shows a claimed square only after its replay finishes.
- Claims only on the main board (every mode): a mini-game view shows its own winning moment, never an X/O claim, stamp or "square won" message; the square turns X or O with the stamp after zooming out. Super Chaos claims come after the round resolves, shown on the board a square at a time once both moves have been shown (the winner's label and stamp; a square both won: both marks clash, then it resets, no claim). A player's own move always plays out fully (its animation and result, e.g. the Roulette spin) right after they make it, before any waiting screen, opponent replay or recap: a result of their own progress is never put off to the round's end. Only a result that needs both moves (a Bump knock, Mini Golf's shared shot) is settled at the round's end (`scMerge` returns `resolve`, or `replay`) and played in its square first. On a shared board where the other player's move can change the outcome (Clash Grid's collisions, Battleship's last parts), the mover's own screen never shows a win, a line or a sink: their move plays unjudged (`scApply`), and lines and wins are looked for only at the round's resolution, after both moves (and any collision block) apply, as with Roulette and Mini Golf (`scMerge`; `resolve` plays it in the square). The main board never shows anything of the opponent's move (a miniature's change, a claim, their last-played badge) until that move's replay has played (`scShown`: `recap.mine`). After locking in, a player sees their own outcome before anything else (online and vs the computer): a result settled only at the round's end (Mini Golf's shots, Roulette's shared spin, a Bump knock, Clash Grid, Sniff, any game whose result needs both moves) plays in their own square first (`core/chaos.js` `scRecapOrder`). Both in the same square: once both are in, the joint resolution plays there in the player's own view (both shots, the shared spin, both moves and any collision: `scMerge` `resolve` with `joint`), its result held, and that square gets no opponent replay. The opponent elsewhere: own outcome first, then the opponent's replay. A phone that joins a recap late (out of sight, the menu open, reopened) still plays its own outcome from its start.
- Opponent moves (computer or online) are shown: highlight the square on the main board, zoom in, play the move with normal animation at human-like pacing, return. Real-time games show the opponent's attempt live.
- Every game must record and replay opponent moves through the shared replay system (`core/replay.js`, `ui/replay.js`): a move carries a compact log (its inputs with their timings, or the run's/attempt's own log or recording) that plays back deterministically through the game's normal view: the selection pressed and typed in, then the move. Online the log rides the move; the computer's moves get one too. Replays play at normal speed with a Skip button after 2 seconds; every replay (all games, all modes, the Super Chaos pop-up too) plays through to the end of the move, every animation of it finished, and holds the final state, the score updated, for about 1 second before it closes (a game's `flashMs` covers all its move's animations; the hold comes after); Super Chaos replays the computer's round at 2x in a pop-up over its square (idle gaps over 0.3 s cut to 0.3 s, a "[name]'s move — replay" banner, a frame in its colour, a replay icon, tap anywhere to skip; Mini Golf's shared shot is the reference), and the board badges each player's last-played square. A game whose view plays the mover's screen from the flash itself (a run, an attempt, a reveal, a throw) says so (`OWN` in `ui/replay.js`); one with a draft (letters, pegs, numbers, cards, a two-tap aim, a pull) adds `replay` hooks (`input`, `synth`) in its `view.js`.
- No help text inside mini-games. Instructions live only in the "?" explainer: "Name — Play: … Win: …", plain and short.
- Sound: one AudioContext, resumed on every tap and whenever the page becomes visible. Game inputs play only their own sound, never the UI click. CC0 or synthesised sounds only, listed in SOUNDS.md.
- Mobile: touch-action none on play areas; no long-press magnifier, selection or callout; no tap highlight; no horizontal scrolling; aim for 60fps. Inputs can start anywhere on the mini-game screen.
- Original art only. No characters, logos or names from existing games or brands. Colours and fonts come from the shared style tokens.
- Online: Find Match is server-authoritative. Hidden information (answers, decks, hidden cells) stays on the server until revealed. Physics games: the client sends aim and power, the server simulates and sends a recording, both phones replay it. Real-time skill games report results that the server sanity-checks.
- Release control: new games default to Admin only. Admin-only games never appear to non-admins anywhere, and never in Find Match.
- Mode: one selector, Super Chaos | Classic (`net/releases.js` `scMode`/`setMode`, kept on the device; `ui/screens/setup.js` `modeRow`), in Play Local and the host's lobby. It shows only where Super Chaos is open to the player (admin, or `releases/superchaos` on, the admin's Releases page); otherwise Classic only, no selector. Find Match is Super Chaos only, run by the server (`core/scgame.js`: the record with every secret and each side's progress; `functions/index.js` `changeSc`, `scMove`, `scTick`, `scBegin`; the phone sends each step as a request, `net/chaos.js` `scRequest`, and plays the answer; `games/{id}/sides/{side}` is a side's own node). The Classic queue (`serverRules.js` `QUEUES.match`, `move`/`timeout`) stays as code, unused, reachable only by the tests. Bots play Super Chaos there by `scCpu` at the admin's level (`planScBot`/`runScBot`), counted apart. Ranked, when it comes, is these matches.
- Turn timer: one deadline per turn, never reset by actions within a turn.
- Stats count only squares that ended claimed by X or O, and none from abandoned matches (resigned, lost on time, never finished). Bot games are tracked separately; Super Chaos squares (computer and friend rooms) under `chaos`. Match averages cover finished matches only.
- Balance targets: about 4–6 of a player's own moves to win a square; no guaranteed wins in 2 moves; every move should help the mover more than the opponent (no waiting traps); first-mover win rate under 60%. Tunable values live in the admin config, not in code: a new tunable goes in the game's `TUNE` (Mini-game Settings).
- Shared components: quiz games (Trivia, Patterns, Geo Quiz) use the quiz component (Reveal locks the player in, cross-outs centred and shared, question persists until solved, button press feedback). Runners use the runner framework. Attention games use the attention framework (Start locks the player in, 3 levels, first to 3 correct).
- Data attribution: Open Trivia Database (CC BY-SA 4.0), OEIS (CC BY-SA 4.0), VisualPuzzles (MIT), Natural Earth (public domain), flag-icons (MIT). Credits screen and README.
- Ratings and the leaderboard are off (RATINGS_ENABLED = false). Don't re-enable without being asked.

## Workflow
- When debugging a match issue, ask me for the exported match log (the admin's Match inspector → Export) if one isn't attached.
- Keep changes scoped to what's asked. Touch only the relevant game folders.
- Run `npm test` for the games you changed. Run simulations only when a prompt asks or when changing a game's balance.
- Don't stop for review unless the prompt asks. If something is ambiguous, pick the option most consistent with these rules and note it.
- Deploy once at the end with deploy.sh.
- Finish with a short report: what changed, anything skipped or uncertain, and the live URL. Keep it under 10 lines.
