# Tic Tac Chaos: project notes

Tic-tac-toe where every square is a mini-game. Mobile-first web game on Firebase Hosting, with Firebase (Auth, Realtime Database, Cloud Functions) for online play.

## Environments (read first)
- **Staging**: https://staging.tictacchaos.com, its own Firebase project (`.firebaserc` alias `staging`), the `staging` branch. **Production**: https://tictacchaos.com (www redirects to it), the project `tic-tac-chaos` (alias `production`), the `main` branch. The old GitHub Pages address redirects to tictacchaos.com.
- **Always work and deploy on `staging`**: `npm run deploy:staging -- "message"` commits and pushes to `staging`; the Deploy workflow (`.github/workflows/deploy.yml`) runs the tests and deploys the site, functions and rules to staging. Report the staging URL (https://staging.tictacchaos.com) after every change.
- **Production only on "release"**: deploy to production only when I explicitly say "release". Then run `npm run release` (from a clean checkout at staging's tip): it runs the tests, checks staging's deploy of that commit passed, lists the commits, asks for confirmation (type `release`) and fast-forwards `main` to `staging`; the push to `main` deploys production. Never push to `main` any other way, never deploy to production by hand, never dispatch a production run.
- The page picks its Firebase project by address (`src/env.js`, `window.TTC_ENV`; only the production hostnames get production, every other address gets staging). Staging data never mixes with production: separate projects, separate keys (each GitHub environment's `FIREBASE_SERVICE_ACCOUNT`; `scripts/check-key.js` refuses another project's key).
- Staging is gated: noindex (meta tag and robots.txt, `scripts/build-site.js`), a "STAGING" badge, and only accounts on the allowlist get in (the admin page's Staging Access, `admin/staging/allow`; `functions/index.js` `stagingAccess` puts a `staging` claim on the account; staging's server calls refuse anyone without it, `functions/.env.staging`; staging's rules are production's with every grant gated, `scripts/staging-rules.js`, applied by the staging deploy only). ## Architecture
Plain ES modules, no build step: Firebase Hosting serves the files as they are (`scripts/build-site.js` only copies them into `_site/`, stamps the version and, on staging, adds noindex).

- `index.html`: the shell (meta tags, `#app`, `src/ui/fonts.css`, `src/ui/styles.css`, `src/env.js` (the Firebase project by address, the staging badge), `src/main.js` as a module).
- `src/main.js`: the entry. Loads every game's `view.js` (by the registry), registers the listeners in a fixed order, renders the sounds, boots.
- `src/core/`: the engine, pure (no page, no clock, no `Math.random`; every random choice from an rng passed in). `board.js` main board, turn flow, win and draw; `match.js` setup and new matches; `minis.js` a square's mini-game through the registry; `timer.js` one deadline a turn, playback timings; `random.js` seeded randomness; `ai.js` the computer on the main board (three levels: Easy, Normal, Hard; `cpuMove(state, rng, style, opts)`, opts.level/clock/budget); `aiw.js` the levels and the Hard weights (`config/ai`, tuned by `npm run tune-ai`); `mc.js` Hard's square choice by Monte Carlo playouts (a square it is close to winning that matters on the board, `ai.js` `closeTo`/`CLOSE`, comes first, but for a block of the other side's match); a square counts as a lost cause (`catchUp`) only where the other side leads, judged by `raceChance` (sharper than `winChance`, checked against Risky Rolls' exact odds); Risky Rolls' `needs` and `q` come from its turn odds (`pig/ai.js` `pigTurns`, `pigReach`); tempo play: Hard leaves a square it safely leads for now and plays elsewhere (`ai.js` `safeLead`: the other side needs more than `margin` moves more than it does, `config/ai` `margin`, 2 by default, Bot Settings' Tempo play, never tuned; in a luck game the other side's chance of catching up within that margin under `SAFE.risk`, a game's own `catchRisk` where it has one (Risky Rolls), else `raceChance`; no threat of the other side's line elsewhere; not a square it must take now to block or complete a line), and comes back once the gap is down to the margin (`mc.js` passes over a safe square; `tests/core/ai.test.js` tempo play); `chaos.js` Super Chaos (simultaneous rounds vs the computer, or a friend in a room); `scgame.js` a Super Chaos match from Find Match as the server runs it; `records.js` online match records (secrets kept apart); `games.js` release control; `config.js` tunable settings; `replay.js` a move's replay log (its shape and limits; the server keeps it on the move's entry); `tune.js` every game's settings (`config/tune/<type>`: `tuneLive(type)` when dealing a square, `tune(mini)` after; a square keeps its values in `mini.tune`); `client.js` (client versions and platforms: `CLIENT_VERSION`, `clientTypes`, `needsUpdate`; see Clients below), `stats.js` (also `topOpponents`/`oppTally`: a profile's Top opponents, from the server's `oppStats` tally), `verify.js` (what the server holds a phone's move to beyond the rules: no timeouts, runs and attempts as their inputs within the time, attention answers after Start and in time), `util.js`. `engine.js` gathers the engine's public names (the server and tests use it as `E`).
- `src/games/<game>/`: one folder per mini-game (50, including the retired Dice race and Hexapawn).
  - `rules.js`: pure logic, shared with the server. Hooks the core calls: `create`, `apply`, `publicView`, `randomMove`, `moveFlash`, `secret`, `hide`, `flashMs`; Super Chaos's `scCreate`, `scRound` (a draw both moves that round share), `scFork`, `scApply`, `scAfter`, `scMerge` where a game needs them.
  - `ai.js`: `needs` (moves still needed) and `best` (the computer's move; `ctx.level` 'easy' | 'normal' | 'hard' and `ctx.until`, the ms a Hard search may still spend, null for a fixed amount of work: Hard searches or plays by expected value there, Normal is never changed by it).
  - `meta.js`: `info` (name, hint), `category` (its label at the top of its "?" explainer, e.g. "More luck"), `EXPLAIN_KEYS` where the explainer fills a `{setting}` from the game's own config rather than `TUNE` (Risky Rolls' `{target}`, `ui/explainer.js` `fillTune`), `explainer` ({ name, play, win } for the "?"), `icon`, `release` ('admin' or 'released'), `minVersion` (the oldest client version that has the game: `core/client.js`), `turnSecs` (an online turn's seconds in this game where it needs more than the match's 30: `core/timer.js` `turnSecs`), `realTime` (its move is a recording or a timed round: played back at the replay's speed, never at the game's pace: `core/timer.js` `moveRate`), `superChaos` (dealt in Super Chaos), `scOnly` (never in a normal match) and `scExplainer` where its rules differ there, default settings (`*_DEFAULTS`), `TUNE` (its settings for the admin's Mini-game Settings: `{ k, label, def, min, max, step, group }`; `{k}` in an explainer shows the value).
  - `view.js`: `screen`, `miniature`, `moveText`, `sounds`, `actions` (its own `data-act` controls), `replay` (hooks for the shared replay: `input`, `synth`) where it keeps a draft, its drawing, animations and input.
  - A hook a game lacks falls back to the core's default. Five Letters and Hangman keep their word lists in `words.js`.
  - Names (October 2026): Craps is shown as "Krabs", Roulette as "Little Wheel", Blackjack as "21" (their ids stay `craps`, `rl`, `bj`, so their stats and history stay attached); no gambling words in them: Little Wheel's players pick, not bet (no chips, wagers or payouts), and a spin's result says Hit or Miss alone beside the number (`rl/view.js`; the number in a round chip, `.rlnum`, at every size), 21's tie is a tie, Krabs says first roll and out, not come-out and craps. These notes still call them by their old names in places. Hot streaks (November 2026): in Krabs, 21 and Little Wheel a win that doesn't take the square keeps the turn (`again`: Krabs rolls a new round, 21 taps Deal for another hand, ties still re-deal, Little Wheel spins again; explainers "Win? Go again."); a loss or miss ends it; a timed-out player gets no extra go (`core/board.js` `timeoutClose`); none in Super Chaos (each `scApply` one round).
  - Four in a Row's piece lands with a soft wooden thunk (`c4drop`; nothing as it falls).
  - Five Letters: no offensive answers or guesses (`core/badwords.js` is the username profanity list, shared with `functions/badwords.js`; `BAD5` in `words.js`; a refused guess says "Not allowed" and costs nothing); each guessed row carries the guesser's mark. Bowling: a turn is one roll at a fresh rack, every pin down counts with no bonuses, the target is its `target` setting (`bowlTarget`); the score boxes beside the lane (one roll each: pins, running total) are drawn on the canvas (`drawFrames`), an empty first box for each player from the moment the square opens, and fill in once the recording has played; the 35 target is set in the database by `scripts/set-releases.js` (`TUNE_SETS`), default 35. Risky Spins (October 2026, `CLIENT_VERSION` 1.2.0; two wheels from November 2026, `CLIENT_VERSION` 1.4.0) is push your luck like Risky Rolls: two wheels of ten segments dealt per square, the safe one and the risky one, each with skulls (low 2, high 5 of 10: `SKULL`), the riskier wheel the bigger values (only the high one has a 10; the medium wheel and its `midSkulls`/`midLo`/`midHi` settings are gone, a stored config that still has them is read without them, `set-releases.js` `wheels3` writes the two-wheel node; a square already dealt with three wheels plays out with them: `rules.js` `wheelsOf`, `WHEELS_ALL`, the AI, the table (`.rwrow.n2`/`.n3`) and the miniature (`.twh.n2`/`.n3`) all read the wheels the square has); a turn spins either wheel each time into a `+N` pot (`mini.turn`, `again`), Bank adds it, a skull loses it; the target (30), skulls and ranges are the admin's (`config/wheels`; a config without `highSkulls` is from before and ignored); the wheels are worth about the same a turn (November 2026: each wheel's expected bank per turn at its best bank point, `rules.js` `wheelTurn`, within `evSpread`, 10%, of the others; the deal redraws until it holds, `wheelsSpread`; set in the databases by `scripts/set-releases.js` `wheels2`), so the choice is risk style; the winning Bank fills the gauge and counts the score up first, then the win shows (`tests/ui/wheels-bank.test.mjs`); a square dealt before (no `v: 2`) plays its old rule to its end. Its computer: Normal banks at the best turn's pot, more when behind, choosing the wheel by its gain against the pot at risk; Hard by the exact race (`wheels/ai.js` `wheelsRace`). Apple Pick (November 2026, `CLIENT_VERSION` 1.3.0, Admin only, `apple`): one tree holds both players' apples (X's red, O's yellow, each player's apple i with its own place on the canopy) and each player's bucket stands under it, side by side, labelled with their mark (`apple/view.js` `orchard`; the rules are per player: a bucket and the apples left for them); a move is one spin (pick 1-4 apples into the bucket, a Bird takes `birdTakes` back, a Spill puts `spillPct` of the bucket back); the first bucket full (`apples`) wins; the wheel's segment mix and all of it in `TUNE` (tuned to about 5 spins for the winner, `tests/sim/apple.sim.js`); the spin and its landing drawn on the server (`at`); replays play from the recorded flash; the miniature a tiny tree with both players' apples left on it and the two buckets with their counts; a move is played in the orchard as it was made, a pick dropping that player's apples from the tree into their bucket, a bird taking theirs back (it comes in from the side their bucket is on) and a spill tipping their bucket towards the tree; the spinner's bird segment is `.abird`, never `.bird` (the swooping bird's animation: its wedge once flew across the wheel). Miniatures (November 2026): every game's miniature is a small picture of the game with the players' progress beside it, never numbers or text alone (`ui/thumbs.js` `thumbArt`, `pipRows`; `tests/ui/miniatures.test.mjs` holds every dealt game to a picture and to public information); a miniature's classes are its own, never the interface's (`.back` is the Back button, `.sq` the board's tile: a card back once took the Back button's look over the win counters; `tests/ui/miniatures.test.mjs`); Risky Spins' skull segments are near-black with the skull (the miniature draws the wheels with the dark segments but no skulls, and each player's score under them), its 10 gold (`--gold`), the other values light-to-dark by value, never near the skull's shade; no game's hazard shares a colour with a reward. New skill games (November 2026, `CLIENT_VERSION` 1.5.0, all Admin only, each `turnSecs: 60`, `realTime`): Muncher (`muncher`: a 9x7 maze from four layouts, a dot on every other open cell; each player's dots are their own (`mini.ate[p]`); a swipe queues a turn for the next tick, up to 2 waiting (`rules.js` `snakeQueue`; a reversal of the last queued direction or a non-turn is ignored), logged as queued and replayed through the same queue by the server, the replays and the AI; `snkGulp` with the 'error' buzz), and the other player reaching the target from your run ends it and hands them the square (`winner`, note `gift`); first to `target` 30; the computer steers for its colour round the other's, loses track after a food now and then (`aiSlip`), Hard the best of 2 runs within `ctx.until` and loses track less often (`aiSlipHard` 15 against Normal's 18); Roads: once one side could not even tie the other's longest road with every open edge, the square ends at once for the longer road (`rules.js` `apply`, note `decided`). Districts: a region locks for its leader once the empty spots touching it could not change who leads it (drawn darker in their colour; `rules.js` `distTally` `lock`), and the first to lock more than half the regions (3 of 5) takes the square at once (`distResult`, note `locked`); a full map goes to whoever leads more regions, and a level count is a draw (the square resets, `note: 'tie'`); a level region is nobody's. Hex: 5x5 (`HEX_N`; a 4x4 square from before plays on, its size from its cells, `hexSize`) with the swap rule: right after the first stone, alone in the square, the other player may play `'swap'` and take it as theirs, once a square (`hexCanSwap`; the view's Swap button, its row always reserved); the computer swaps and opens by a book from Hard-against-Hard play (`HEX_SWAP`: the stones worth taking; `HEX_OPEN`: its openings, the edge cells of the first and last rows; O's the same turned round the long diagonal, `hexT`); `tests/sim/hex.sim.js` measures the first mover (October 2026: 66% in turn with Normal, 82-86% with Hard, 65-71% in whole matches with the any-square rule; 4x4 had been 50%/100% in turn and 33%/97% in matches), so Hex is Admin only (`scripts/set-releases.js` `rel3`) until it is under 60%. Pool: three balls each (x1-x3, o1-o3; two rows of three, alternating); the first to sink all of their own on the table wins (`pool/rules.js` `poolLeft`); a ball sunk for the other side counts for them; every scratch puts the white back and a ball back for the shooter on a free spot (one of their own pocketed, else a new extra ball in their colour, `poolExtra`: x4, x5 ...; two scratches in a row add two), nothing for the other side, so a shot that sinks the last ball and scratches does not win; the black loses; both sides' last balls down on the one shot is a draw (the square resets: `rules.js` `apply`, note `tie`; the computer scores it 0, `physScore`). Each side's balls left on the table show as a number by its name and in the miniature; the miniature is the table itself (rails, felt, six pockets) with the balls on it, drawn from its own copy of the table's sizes before the physics library has loaded (`pool/view.js` `POOL_TABLE`; `tests/ui/pool-mini.test.mjs`), sized in the square's container units (`.tpool .tphys` `72cqh` and the table's aspect: a percentage height resolved to nothing in Safari and the table vanished while the counts showed, November 2026). After a scratch, the ball put back for the shooter pops onto its spot once the shot has played, with a short "+1 ball" in their colour (`ui/physics.js` `poolPop`, `POOLG.pop` in `flashMs`; a `pop` sound), before the square closes. Mini Golf's computer also tries shots past the bumpers in its way and off them (their kick in the simulation: `shared/physics.js` `golfBumperShots`), then takes the best few again with its own aim error either way and keeps the one that does best over all three (`GOLF_ROBUST`).

## Adding a mini-game
Create src/games/<name>/ with rules.js, view.js, ai.js and meta.js, and register it. Every game needs: its settings (`TUNE` in meta.js, every tunable value), an explainer (in the format below), AI with a Hard form where the game has choices (`best` reads `ctx.level === 'hard'` and keeps to `ctx.until`), a miniature for the main board, AI, what a timeout leaves of a move under way (no move is played for a player out of time: `timeoutClose` where a begun move must end), animations, sounds, stats tracking, a default release status of Admin only, its `minVersion` (`CLIENT_VERSION` bumped to it when the game is new: `core/client.js`), a category in its meta.js (`category`: 'luck', 'skill' or 'brain': shown as "More luck" etc. at the top of its "?" explainer; the Mini-games checklist is one alphabetical list).

## Standing rules (apply to every change)
- Lists fit the screen: a game-history row is a block button holding a grid (`.hirow .hin`) whose columns all shrink, so its board snapshot, texts and badges stay inside the row at 360px. The snapshot is always a square 3x3 (`.hsnap`: fixed equal rows and columns and a square box, however few squares are filled, never stretched).
- Every mini-game must fit the screen with no scrolling, at any phone size down to 360x640: size its controls (a number grid, a keyboard, a board) from the space available, never from fixed pixels, with status and result text in reserved space.
- Layout never shifts. Reserve fixed space for status, result text and buttons; no board moves when text appears or disappears. Text never overlaps: a move's result text (live or in a replay, normal and Super Chaos) goes in its game's reserved result area and never covers other text or the game's drawing; text that swaps in over time (`.tu`/`.tf`/`.tu2`) shows one line at a time. Names and score bars: a player's name and their figures each keep their own room and never overlap, at any width: in a tally (`.ctal`, `progress.js` `arcTally`, the name `.tnm`) the name gives way with "…" down to about three letters, then the figures go to a line of their own under it (decided by the tally's width and the figures' reserved widths alone, so a tally never changes shape mid-match); `.ctals` columns are `minmax(0, 1fr)`; a name inside a line of text or a button (`.hn`, `.bnm`, Roulette's bets, a wheel's or die's label) is cut short with "…" rather than wrapping onto what is below; a game's play area sizes from the room the header leaves (Echo's pads, `100cqh`), never riding up over it. `npm run check:headers` (`scripts/check-headers.js`, Playwright) opens every mini-game with long names at 320, 360, 390 and 430 px and fails on any overlap, a name cut without "…" or under 40px, or scrolling.
- Animations and sounds fire exactly once, from the move event that caused them, never from rendering or re-rendering. The main board shows a claimed square only after its replay finishes.
- Claims only on the main board (every mode): a mini-game view shows its own winning moment, never an X/O claim or stamp; its result says only "Won by" and the winner's mark, or "Draw" (`ui/mini.js` `squareEnd`, `wonBy`: the header's result line live and in replays, a held result, a finished square's review; no word revealed, score or reset named; a game's own result line names the move alone, e.g. Pool's "The black!"); the square turns X or O with the stamp after zooming out. Super Chaos claims come after the round resolves, shown on the board a square at a time once both moves have been shown (the winner's label and stamp; a square both won: both marks clash, then it resets, no claim). A player's own move always plays out fully (its animation and result, e.g. the Roulette spin) right after they make it, before any waiting screen, opponent replay or recap: a result of their own progress is never put off to the round's end. Only a result that needs both moves (Mini Golf's shared shot, a Bump knock) is settled at the round's end (`scMerge` returns `resolve`, or `replay`) and played in its square first. Bump: the spin plays at once in the player's own square (the wheel, their own piece's hops; nothing knocked yet); the round's end settles the knocks (`scMerge` `resolve`): if both spun there, both pieces hop together from where the round began, with any bump, as that square's joint resolution (no separate opponent replay), and the board settles to its final positions; the other player's lone spin is their replay, then any knock. Both moving in one shared square of Candy Race, Snakes and Ladders or Treasure Hunt (`rules.js` `scJoint`, `core/chaos.js` after `scMerge`): the recap plays both moves together in the player's own square from where the round began (`ui/track.js` `trackRoundEnd`; both digs open together), with no separate opponent replay, and the square settles to both. Every joint replay (both players in one square: Mini Golf's shots, Bump, Candy Race, Snakes and Ladders, Treasure Hunt, Sniff, Roulette's shared spin, Standoff Grid) uses the standard replay frame like any opponent replay: the pop-up over the board, the banner ("Both moves — replay"), the opponent's colour border, a Skip after 2 seconds and tap anywhere to skip (`ui/chaos.js` `scJointFrame`, `scSkip`; `ui/mini.js`). Super Chaos against the computer has no round clock (`sc.deadline` stays unset; `ui/chaos.js`, `clock.js`, `turnbar.js` show one only online). On a shared board where the other player's move can change the outcome (Standoff Grid's collisions, Sea Battle's last parts), the mover's own screen never shows a win, a line or a sink: their move plays unjudged (`scApply`), and lines and wins are looked for only at the round's resolution, after both moves (and any collision block) apply, as with Roulette and Mini Golf (`scMerge`; `resolve` plays it in the square). The main board never shows anything of the opponent's move (a miniature's change, a claim, their last-played badge) until that move's replay has played (`scShown`: `recap.mine`). No main-board change before its replay, on every path (claims, resets and the new mini-game a reset deals, miniatures; online, server-run and vs the computer, a late join or a reload): a square both won shows its old game until its replay or joint resolution has played, then clashes and resets (`scShown` treats a recap not yet under way as its waiting stage, never as the settled board). No gap between waiting and replay: the opponent's replay is available as soon as their move's result is known (online, the waiting phone starts the recap at once; only the last mover's phone starts it after its own result, `recap.lead`), and the waiting band ("Waiting for [name]…", `board.js` `waitBand`) stays up until the replay is ready to play. A player waiting in their own square for the round's end (Mini Golf, any joint-resolution game) sees that same band over the game, not small text. After locking in, a player sees their own outcome before anything else (online and vs the computer): a result settled only at the round's end (Mini Golf's shots, Roulette's shared spin, a Bump knock, Standoff Grid, Sniff, any game whose result needs both moves) plays in their own square first (`core/chaos.js` `scRecapOrder`). Both in the same square: once both are in, the joint resolution plays there in the player's own view (both shots, the shared spin, both moves and any collision: `scMerge` `resolve` with `joint`), its result held, and that square gets no opponent replay. The opponent elsewhere: own outcome first, then the opponent's replay. Both in the same square of an individual-progress game (Risky Spins, Blackjack, Higher/Lower: nothing settled jointly): no joint resolution, so each still sees the other's replay. The opponent's replay always plays from its start the first time a phone reaches it (a phone held up, frozen or out of sight rewinds the recap to it: `ui/chaos.js` `oppCatchUp`), never a moment of it; a replay that cannot play is logged to the match log (`devError('replay')`), never shown as an empty pop-up. A phone that joins a recap late (out of sight, the menu open, reopened) still plays its own outcome from its start.
