# Tic Tac Chaos: project notes

Tic-tac-toe where every square is a mini-game. Mobile-first web game on Firebase Hosting, with Firebase (Auth, Realtime Database, Cloud Functions) for online play.

## Environments (read first)
- **Staging**: https://staging.tictacchaos.com, its own Firebase project (`.firebaserc` alias `staging`), the `staging` branch. **Production**: https://tictacchaos.com (www redirects to it), the project `tic-tac-chaos` (alias `production`), the `main` branch. The old GitHub Pages address redirects to tictacchaos.com.
- **Always work and deploy on `staging`**: `npm run deploy:staging -- "message"` commits and pushes to `staging`; the Deploy workflow (`.github/workflows/deploy.yml`) runs the tests and deploys the site, functions and rules to staging. Report the staging URL (https://staging.tictacchaos.com) after every change.
- **Production only on "release"**: deploy to production only when I explicitly say "release". Then run `npm run release` (from a clean checkout at staging's tip): it runs the tests, checks staging's deploy of that commit passed, lists the commits, asks for confirmation (type `release`) and fast-forwards `main` to `staging`; the push to `main` deploys production. Never push to `main` any other way, never deploy to production by hand, never dispatch a production run.
- The page picks its Firebase project by address (`src/env.js`, `window.TTC_ENV`; only the production hostnames get production, every other address gets staging). Staging data never mixes with production: separate projects, separate keys (each GitHub environment's `FIREBASE_SERVICE_ACCOUNT`; `scripts/check-key.js` refuses another project's key).
- Staging is gated: noindex (meta tag and robots.txt, `scripts/build-site.js`), a "STAGING" badge, and only accounts on the allowlist get in (the admin page's Staging Access, `admin/staging/allow`; `functions/index.js` `stagingAccess` puts a `staging` claim on the account; staging's server calls refuse anyone without it, `functions/.env.staging`; staging's rules are production's with every grant gated, `scripts/staging-rules.js`, applied by the staging deploy only). Seeded by `scripts/seed-staging.js` (test accounts, the admin), never with production data.
- Security (the October 2026 review, Phase 1): every online match is the server's (above); game content is escaped in every view (`esc`) and a record is held to its shape (`core/records.js` `parseMatch`: `tests/ui/xss.test.mjs`, `tests/core/parse-match.test.js`); the site sends a CSP and the other security headers (`firebase.json`, `admin.html` never framed); `track` and `devlog` need a login (the page signs in anonymously first: `net/tracking.js`), are rate-limited per caller (`functions/index.js` `rateOk`, `rate/{minute}`), new devices are capped per day, and a match's log never grows past `LOG_CAP`; App Check (reCAPTCHA Enterprise: `src/env.js` `appCheckKey`, `connect.js` `appCheck`) is wired and off until the keys exist, enforced on the functions by `TTC_APPCHECK=enforce` in `functions/.env.<project>`; the alert keys move to Secret Manager (`defineSecret`, bound once `TTC_SECRETS=on` in `functions/.env.<project>`: `firebase functions:secrets:set TWILIO_SID TWILIO_TOKEN TWILIO_FROM RESEND_KEY EMAIL_FROM`; the deploy makes placeholders; `admin/secrets` is read only until then and never backed up); the trivia workflow takes its inputs through env and never writes `main` or `staging`; `firebase-tools` is pinned; Matter.js loads from the site first. F3 (the skill games' results): see the Online standing rule (`core/verify.js`, `FIND_MATCH_HOLD`).
- `npm run check:envs` shows what is live where (each site's `version.json` against `main` and `staging`). The staging deploy also prints it, with a check of the old GitHub Pages redirect (a report, never a failure).
- Launch reset (`.github/workflows/reset-production.yml`, `scripts/reset-production.js`): manual, production only, dry run by default, deletes only with `RESET-PRODUCTION` typed; backs the whole database up first (`gs://tic-tac-chaos-backups/backups/<time>Z.json.gz`, read back and checked), then deletes matches, history, match logs, stats and tracking and puts every record at 0-0-0; accounts, usernames, admin, config, releases, features, bots, meta, review, prefs stay. Undo: `restore-production.yml` (`scripts/restore-backup.js`, `list` or a backup's name plus `RESTORE-PRODUCTION`; it saves the database first). Never run either unasked.

## Architecture
Plain ES modules, no build step: Firebase Hosting serves the files as they are (`scripts/build-site.js` only copies them into `_site/`, stamps the version and, on staging, adds noindex).

- `index.html`: the shell (meta tags, `#app`, `src/ui/fonts.css`, `src/ui/styles.css`, `src/env.js` (the Firebase project by address, the staging badge), `src/main.js` as a module).
- `src/main.js`: the entry. Loads every game's `view.js` (by the registry), registers the listeners in a fixed order, renders the sounds, boots.
- `src/core/`: the engine, pure (no page, no clock, no `Math.random`; every random choice from an rng passed in). `board.js` main board, turn flow, win and draw; `match.js` setup and new matches; `minis.js` a square's mini-game through the registry; `timer.js` one deadline a turn, playback timings; `random.js` seeded randomness; `ai.js` the computer on the main board (three levels: Easy, Normal, Hard; `cpuMove(state, rng, style, opts)`, opts.level/clock/budget); `aiw.js` the levels and the Hard weights (`config/ai`, tuned by `npm run tune-ai`); `mc.js` Hard's square choice by Monte Carlo playouts (a square it is close to winning that matters on the board, `ai.js` `closeTo`/`CLOSE`, comes first, but for a block of the other side's match); a square counts as a lost cause (`catchUp`) only where the other side leads, judged by `raceChance` (sharper than `winChance`, checked against Risky Rolls' exact odds); Risky Rolls' `needs` and `q` come from its turn odds (`pig/ai.js` `pigTurns`, `pigReach`); tempo play: Hard leaves a square it safely leads for now and plays elsewhere (`ai.js` `safeLead`: the other side needs more than `margin` moves more than it does, `config/ai` `margin`, 2 by default, Bot Settings' Tempo play, never tuned; in a luck game the other side's chance of catching up within that margin under `SAFE.risk`, a game's own `catchRisk` where it has one (Risky Rolls), else `raceChance`; no threat of the other side's line elsewhere; not a square it must take now to block or complete a line), and comes back once the gap is down to the margin (`mc.js` passes over a safe square; `tests/core/ai.test.js` tempo play); `chaos.js` Super Chaos (simultaneous rounds vs the computer, or a friend in a room); `scgame.js` a Super Chaos match from Find Match as the server runs it; `records.js` online match records (secrets kept apart); `games.js` release control; `config.js` tunable settings; `replay.js` a move's replay log (its shape and limits; the server keeps it on the move's entry); `tune.js` every game's settings (`config/tune/<type>`: `tuneLive(type)` when dealing a square, `tune(mini)` after; a square keeps its values in `mini.tune`); `client.js` (client versions and platforms: `CLIENT_VERSION`, `clientTypes`, `needsUpdate`; see Clients below), `stats.js` (also `topOpponents`/`oppTally`: a profile's Top opponents, from the server's `oppStats` tally), `verify.js` (what the server holds a phone's move to beyond the rules: no timeouts, runs and attempts as their inputs within the time, attention answers after Start and in time), `util.js`. `engine.js` gathers the engine's public names (the server and tests use it as `E`).
- `src/games/<game>/`: one folder per mini-game (50, including the retired Dice race and Hexapawn).
  - `rules.js`: pure logic, shared with the server. Hooks the core calls: `create`, `apply`, `publicView`, `randomMove`, `moveFlash`, `secret`, `hide`, `flashMs`; Super Chaos's `scCreate`, `scRound` (a draw both moves that round share), `scFork`, `scApply`, `scAfter`, `scMerge` where a game needs them.
  - `ai.js`: `needs` (moves still needed) and `best` (the computer's move; `ctx.level` 'easy' | 'normal' | 'hard' and `ctx.until`, the ms a Hard search may still spend, null for a fixed amount of work: Hard searches or plays by expected value there, Normal is never changed by it).
  - `meta.js`: `info` (name, hint), `category` (its label at the top of its "?" explainer, e.g. "More luck"), `EXPLAIN_KEYS` where the explainer fills a `{setting}` from the game's own config rather than `TUNE` (Risky Rolls' `{target}`, `ui/explainer.js` `fillTune`), `explainer` ({ name, play, win } for the "?"), `icon`, `release` ('admin' or 'released'), `minVersion` (the oldest client version that has the game: `core/client.js`), `turnSecs` (an online turn's seconds in this game where it needs more than the match's 30: `core/timer.js` `turnSecs`), `realTime` (its move is a recording or a timed round: played back at the replay's speed, never at the game's pace: `core/timer.js` `moveRate`), `superChaos` (dealt in Super Chaos), `scOnly` (never in a normal match) and `scExplainer` where its rules differ there, default settings (`*_DEFAULTS`), `TUNE` (its settings for the admin's Mini-game Settings: `{ k, label, def, min, max, step, group }`; `{k}` in an explainer shows the value).
  - `view.js`: `screen`, `miniature`, `moveText`, `sounds`, `actions` (its own `data-act` controls), `replay` (hooks for the shared replay: `input`, `synth`) where it keeps a draft, its drawing, animations and input.
  - A hook a game lacks falls back to the core's default. Five Letters and Hangman keep their word lists in `words.js`.
  - Five Letters: no offensive answers or guesses (`core/badwords.js` is the username profanity list, shared with `functions/badwords.js`; `BAD5` in `words.js`; a refused guess says "Not allowed" and costs nothing); each guessed row carries the guesser's mark. Bowling: a turn is one roll at a fresh rack, every pin down counts with no bonuses, the target is its `target` setting (`bowlTarget`); the score boxes beside the lane (one roll each: pins, running total) are drawn on the canvas (`drawFrames`), an empty first box for each player from the moment the square opens, and fill in once the recording has played; the 35 target is set in the database by `scripts/set-releases.js` (`TUNE_SETS`), default 35. Sea Battle's shot dots carry the firer's colour; a cell's label names the shooter in plain text, never through `N` (its computer icon's markup broke the attribute and showed on the cell: `tests/ui/bs-hit.test.mjs`). Roads: once one side could not even tie the other's longest road with every open edge, the square ends at once for the longer road (`rules.js` `apply`, note `decided`). Districts: a region locks for its leader once the empty spots touching it could not change who leads it (drawn darker in their colour; `rules.js` `distTally` `lock`), and the first to lock more than half the regions (3 of 5) takes the square at once (`distResult`, note `locked`); a full map goes to whoever leads more regions, and a level count is a draw (the square resets, `note: 'tie'`); a level region is nobody's. Hex: 5x5 (`HEX_N`; a 4x4 square from before plays on, its size from its cells, `hexSize`) with the swap rule: right after the first stone, alone in the square, the other player may play `'swap'` and take it as theirs, once a square (`hexCanSwap`; the view's Swap button, its row always reserved); the computer swaps and opens by a book from Hard-against-Hard play (`HEX_SWAP`: the stones worth taking; `HEX_OPEN`: its openings, the edge cells of the first and last rows; O's the same turned round the long diagonal, `hexT`); `tests/sim/hex.sim.js` measures the first mover (October 2026: 66% in turn with Normal, 82-86% with Hard, 65-71% in whole matches with the any-square rule; 4x4 had been 50%/100% in turn and 33%/97% in matches), so Hex is Admin only (`scripts/set-releases.js` `rel3`) until it is under 60%. Pool: three balls each (x1-x3, o1-o3; two rows of three, alternating); the first to sink all of their own on the table wins (`pool/rules.js` `poolLeft`); a ball sunk for the other side counts for them; every scratch puts the white back and a ball back for the shooter on a free spot (one of their own pocketed, else a new extra ball in their colour, `poolExtra`: x4, x5 ...; two scratches in a row add two), nothing for the other side, so a shot that sinks the last ball and scratches does not win; the black loses. Each side's balls left on the table show as a number by its name and in the miniature. After a scratch, the ball put back for the shooter pops onto its spot once the shot has played, with a short "+1 ball" in their colour (`ui/physics.js` `poolPop`, `POOLG.pop` in `flashMs`; a `pop` sound), before the square closes. Mini Golf's layouts are long, winding courses (22 layouts, 42 holes with the mirrors; two are their own mirror image and stay symmetric) with a dense `path` (a point every 5 to 15 units down the middle of the way), and `tests/sim/golf.sim.js` holds them to 4 to 6 putts on average for the computer (each hole 3.4 to 7; every hole solved in 2 to 7 shots; a mirrored wall keeps three decimals so it meets its neighbours as the original does); the computer's candidates include the farthest path points in sight. Mini Golf's computer also tries shots past the bumpers in its way and off them (their kick in the simulation: `shared/physics.js` `golfBumperShots`), then takes the best few again with its own aim error either way and keeps the one that does best over all three (`GOLF_ROBUST`).
- `src/games/shared/`: what a family shares (runner, attention, finger, physics with `physics-sim.js` on Matter.js, cards, lines, placement). A game's `rules.js` re-exports the family's hooks. Pinball's tables live in `physics-sim.js` (`PIN_LAYOUTS`, the lower table, `pinTable`, `pinLayoutCheck`): a square deals a layout and seven of its spots (`pinball/rules.js` `pinDeal`), and `tests/games/pinball.test.js` holds every layout to the layout check (an overlap fails `npm test`, so the deploys).
- `src/games/index.js`: the registry, one line per game (rules, AI, meta) in menu order, retired games last. `TYPES`, `TEST_TYPES` (from `meta.release`), `OLD_TYPES` and `INFO` come from it. The core dispatches with `rulesOf(type).apply(...)`, `aiOf(type).best(...)`, `viewOf(type).screen(...)`.
- `src/ui/`: `app.js` (state, timings, shared helpers), `render.js`, `board.js`, `mini.js`, `turnbar.js`, `turns.js` (computer's turn, result card), `replay.js` (opponent replays: an opponent's logged inputs played through the view, the Skip button; this phone's inputs logged for its moves), `chaos.js` (Super Chaos's round clock, recap and the 2x replay pop-up), `clock.js`, `input.js` (click handler; game controls go to the view's `actions`), `think.js` + `ai.worker.js` (the Hard computer's move worked out in a worker within its budget), `screens/` (among them `stale.js`: an online match with a mini-game this version lacks, Update or Leave match), and the shared components: `attention.js`, `runner.js`, `finger.js` (frameworks), `physics.js` (helpers), `progress.js` (bars, tallies), `explainer.js` (the "?" pop-up), `cards.js`, `track.js`, `keyboard.js`, `art.js`, `fx.js`. `sandbox.js` is the admin's Test play (`?sandbox=<game>&cfg=…`: one mini-game with the editor's unsaved settings, nothing saved). `config.js` holds the storage key and switches (`RATINGS_ENABLED`). `debug.js` puts the page's names on `window` for the browser tests and the console.
- `src/audio/sound.js`: the single sound manager. A replay's sounds are kept under its scope (`SND.scope`: `ui/replay.js` sets it for an opponent's or the computer's replay, `ui/chaos.js` `scPlay` for the recap's), the ones scheduled ahead too, and Skip stops them all at once (`SND.cut`, from `repSkip` and `scSkip`; interface taps are `ui: true`, never a replay's: `tests/ui/replay-skip-audio.test.mjs`). `SND.ensure` checks the context before every sound; any tap silently resumes it (or replaces it in the same tap when it is still down, closed or its clock stopped); the "Tap to restore sound" chip shows only when a tap could not bring it back, until sound runs again; state changes go to the device and match logs (devlog `audio`).
- `src/net/`: `connect.js` (Firebase config, SDK, App Check, server time), `room.js` (friend rooms: the lobby, opened and joined through the server, the match the server runs for it, presence, playback of the opponent's moves), `chaos.js` (Super Chaos online: each step a request to the server, recaps), `moves.js` (every online move is a request to the server), `matchmaking.js` (Find Match, and the listeners every server-run match uses), `accounts.js`, `auth.js` (Google and Apple sign-in: the web's popup or redirect, the app's native sheets through the Capacitor plugin, then `signInWithCredential`), `platform.js` (everything that differs between the web page and the iOS app: the client it reports, sharing, copying, opening outside pages, links that open the game, "Please update"), `releases.js`, `reactions.js`, `tracking.js` (stats and device events: always a signed-in call, anonymously at least).

## Adding a mini-game
Create src/games/<name>/ with rules.js, view.js, ai.js and meta.js, and register it. Every game needs: its settings (`TUNE` in meta.js, every tunable value), an explainer (in the format below), AI with a Hard form where the game has choices (`best` reads `ctx.level === 'hard'` and keeps to `ctx.until`), a miniature for the main board, AI, what a timeout leaves of a move under way (no move is played for a player out of time: `timeoutClose` where a begun move must end), animations, sounds, stats tracking, a default release status of Admin only, its `minVersion` (`CLIENT_VERSION` bumped to it when the game is new: `core/client.js`), a category in its meta.js (`category`: 'luck', 'skill' or 'brain': shown as "More luck" etc. at the top of its "?" explainer; the Mini-games checklist is one alphabetical list).

## Standing rules (apply to every change)
- Lists fit the screen: a game-history row is a block button holding a grid (`.hirow .hin`) whose columns all shrink, so its board snapshot, texts and badges stay inside the row at 360px. The snapshot is always a square 3x3 (`.hsnap`: fixed equal rows and columns and a square box, however few squares are filled, never stretched).
- Every mini-game must fit the screen with no scrolling, at any phone size down to 360x640: size its controls (a number grid, a keyboard, a board) from the space available, never from fixed pixels, with status and result text in reserved space.
- Layout never shifts. Reserve fixed space for status, result text and buttons; no board moves when text appears or disappears. Text never overlaps: a move's result text (live or in a replay, normal and Super Chaos) goes in its game's reserved result area and never covers other text or the game's drawing; text that swaps in over time (`.tu`/`.tf`/`.tu2`) shows one line at a time. Names and score bars: a player's name and their figures each keep their own room and never overlap, at any width: in a tally (`.ctal`, `progress.js` `arcTally`, the name `.tnm`) the name gives way with "…" down to about three letters, then the figures go to a line of their own under it (decided by the tally's width and the figures' reserved widths alone, so a tally never changes shape mid-match); `.ctals` columns are `minmax(0, 1fr)`; a name inside a line of text or a button (`.hn`, `.bnm`, Roulette's bets, a wheel's or die's label) is cut short with "…" rather than wrapping onto what is below; a game's play area sizes from the room the header leaves (Echo's pads, `100cqh`), never riding up over it. `npm run check:headers` (`scripts/check-headers.js`, Playwright) opens every mini-game with long names at 320, 360, 390 and 430 px and fails on any overlap, a name cut without "…" or under 40px, or scrolling.
- Animations and sounds fire exactly once, from the move event that caused them, never from rendering or re-rendering. The main board shows a claimed square only after its replay finishes.
- Claims only on the main board (every mode): a mini-game view shows its own winning moment, never an X/O claim, stamp or "square won" message; the square turns X or O with the stamp after zooming out. Super Chaos claims come after the round resolves, shown on the board a square at a time once both moves have been shown (the winner's label and stamp; a square both won: both marks clash, then it resets, no claim). A player's own move always plays out fully (its animation and result, e.g. the Roulette spin) right after they make it, before any waiting screen, opponent replay or recap: a result of their own progress is never put off to the round's end. Only a result that needs both moves (Mini Golf's shared shot, a Bump knock) is settled at the round's end (`scMerge` returns `resolve`, or `replay`) and played in its square first. Bump: the spin plays at once in the player's own square (the wheel, their own piece's hops; nothing knocked yet); the round's end settles the knocks (`scMerge` `resolve`): if both spun there, both pieces hop together from where the round began, with any bump, as that square's joint resolution (no separate opponent replay), and the board settles to its final positions; the other player's lone spin is their replay, then any knock. Both moving in one shared square of Candy Race, Snakes and Ladders or Treasure Hunt (`rules.js` `scJoint`, `core/chaos.js` after `scMerge`): the recap plays both moves together in the player's own square from where the round began (`ui/track.js` `trackRoundEnd`; both digs open together), with no separate opponent replay, and the square settles to both. Every joint replay (both players in one square: Mini Golf's shots, Bump, Candy Race, Snakes and Ladders, Treasure Hunt, Sniff, Roulette's shared spin, Standoff Grid) uses the standard replay frame like any opponent replay: the pop-up over the board, the banner ("Both moves — replay"), the opponent's colour border, a Skip after 2 seconds and tap anywhere to skip (`ui/chaos.js` `scJointFrame`, `scSkip`; `ui/mini.js`). Super Chaos against the computer has no round clock (`sc.deadline` stays unset; `ui/chaos.js`, `clock.js`, `turnbar.js` show one only online). On a shared board where the other player's move can change the outcome (Standoff Grid's collisions, Sea Battle's last parts), the mover's own screen never shows a win, a line or a sink: their move plays unjudged (`scApply`), and lines and wins are looked for only at the round's resolution, after both moves (and any collision block) apply, as with Roulette and Mini Golf (`scMerge`; `resolve` plays it in the square). The main board never shows anything of the opponent's move (a miniature's change, a claim, their last-played badge) until that move's replay has played (`scShown`: `recap.mine`). No main-board change before its replay, on every path (claims, resets and the new mini-game a reset deals, miniatures; online, server-run and vs the computer, a late join or a reload): a square both won shows its old game until its replay or joint resolution has played, then clashes and resets (`scShown` treats a recap not yet under way as its waiting stage, never as the settled board). No gap between waiting and replay: the opponent's replay is available as soon as their move's result is known (online, the waiting phone starts the recap at once; only the last mover's phone starts it after its own result, `recap.lead`), and the waiting band ("Waiting for [name]…", `board.js` `waitBand`) stays up until the replay is ready to play. A player waiting in their own square for the round's end (Mini Golf, any joint-resolution game) sees that same band over the game, not small text. After locking in, a player sees their own outcome before anything else (online and vs the computer): a result settled only at the round's end (Mini Golf's shots, Roulette's shared spin, a Bump knock, Standoff Grid, Sniff, any game whose result needs both moves) plays in their own square first (`core/chaos.js` `scRecapOrder`). Both in the same square: once both are in, the joint resolution plays there in the player's own view (both shots, the shared spin, both moves and any collision: `scMerge` `resolve` with `joint`), its result held, and that square gets no opponent replay. The opponent elsewhere: own outcome first, then the opponent's replay. Both in the same square of an individual-progress game (Risky Spins, Blackjack, Higher/Lower: nothing settled jointly): no joint resolution, so each still sees the other's replay. The opponent's replay always plays from its start the first time a phone reaches it (a phone held up, frozen or out of sight rewinds the recap to it: `ui/chaos.js` `oppCatchUp`), never a moment of it; a replay that cannot play is logged to the match log (`devError('replay')`), never shown as an empty pop-up. A phone that joins a recap late (out of sight, the menu open, reopened) still plays its own outcome from its start.

- Turn time (online): 30 seconds a turn (Find Match, `FIND_MATCH_TIMER`; a friend game's option is No limit or 30 seconds, `core/timer.js` `TIMER_OPTIONS`; an older room's 1 or 3 minutes becomes 30 s, `normTimer`). A game that needs longer declares it in its meta.js (`turnSecs: 60`: the runners, Sky Hop, Scoop Stack, Pinball, Echo, Snapshot, Risky Rolls; `timer.js` `turnSecs`). Opening such a square on your turn gives the turn that time, counted from the turn's start, and holds the turn to the square, as Start does (`turnOpen`: `timer.secs`, `state.lock` with `lockBy: 'open'`; the page calls the server's `move` kind `open`, `net/moves.js` `dbOpen`, `records.js` `applyOnlineOpen`); the countdown shows the turn's own time (`turnLimit`), the 30 s on the board and in other games. A square only opened, nothing begun there, times out as a missed turn (two in a row: a forfeit), and its first move there is the turn's move, not a bonus (`board.js`). `tests/core/turn-time.test.js`.
- Turn timer: one deadline per turn, never reset by actions within a turn (only lengthened once, by opening a game with time of its own). It starts only once the replays before it are over: in Classic, when the player on the move has finished or skipped the replay of the previous move (their phone starts it on the record, `core/timer.js` `startClock`; at the latest when that replay would have ended, `startBy`); in Super Chaos, the next round's clock starts only when both players have finished or skipped the recap and its replays (`sc.ready`, `applyChaosBegin`/`applyScBegin`; a bot is through at once, a phone gone is waited for `SC_ONLINE.readyWaitMs`).
- Timeouts (all modes): no automatic move, random or otherwise. No phone ever plays a timeout: `'auto'` sent from a phone is refused online (`core/verify.js` `AUTO_FROM_PHONE`; Odd One Out's own pick timer is the one exception, and it only counts against the sender); a timeout move is the server's, from the deadline. A missed turn (or Super Chaos round) does nothing: the turn passes, the round goes on without that player's move. A move already under way ends as it stands (`timeoutClose`: Risky Rolls banks, Blackjack stands, a round or attempt begun fails; a bonus move owed is not taken), which is not a miss. Two consecutive misses by the same player means they surrender and lose the match (`winReason` 'timeout'). Misses are enforced by the server whether or not either phone is open (being away never pauses a turn or round): every online match (Find Match and friend rooms alike) by `games/{id}/dl`, the deadline sweep each minute, the phones' `timeout`/`scTick` calls and a bot's Cloud Task. A forfeit is recorded (stats, history), closes a friend room (`status: 'over'`, no rematch) and shows "[name] forfeited — 2 missed turns" to both phones when they return. The record is the one truth: a phone waiting on the other side asks the server every few seconds (`scTick`, `scBegin`, `tick`), so a dead connection never holds a round. (`core/records.js` still holds the record-transaction engine of the old friend rooms, `applyChaosSubmit`/`applyRoomSweep`/`scResyncPlan`, used by the tests only.)
- Stats count only squares that ended claimed by X or O, and none from abandoned matches (resigned, lost on time, never finished). Bot games are tracked separately; Super Chaos squares (computer and friend rooms) under `chaos`. Match averages cover finished matches only. Every square is recorded: online matches by the server (`finishGame`); a local match's start and its end (every square in it, the match-winning one included: `core/stats.js` `matchStats`) go through an outbox kept on the phone (`net/tracking.js` `track`, `outbox`, `flushOutbox`: sent at once, else kept and sent again on the next report, a return to the page, the network coming back, the next app open and a backing-off retry; dropped only when the server refuses one as malformed, or after a week; the server counts each match's start and end once, `claimMatch`). The admin's Mini-games table shows each game's Completed, Resets (ended level, the board reset) and Left open, and a line that reconciles them (completed + resets + left open = played), Super Chaos and the admin-only games' squares (kept under `testing`) counted apart (`tests/ui/track-squares.test.mjs`).
- No tie goes to either player: a level square is a draw and resets to a new mini-game (Districts' level count and Shelves' level shelves, `note: 'tie'`); no rule gives the second mover an advantage. Without their old tie rules, Districts (first mover 81% of decided squares with Normal, 91% with Hard, 35-39% draws) and Shelves (first mover over 90%) are Admin only until rebalanced (`rel3`).
- Balance targets: about 4–6 of a player's own moves to win a square; no guaranteed wins in 2 moves; every move should help the mover more than the opponent (no waiting traps); first-mover win rate under 60%. Tunable values live in the admin config, not in code: a new tunable goes in the game's `TUNE` (Mini-game Settings).
- Shared components: quiz games (Trivia, Patterns, Geo Quiz) use the quiz component (Reveal locks the player in, cross-outs centred and shared, question persists until solved, button press feedback). Runners use the runner framework. Attention games use the attention framework (Start locks the player in, 3 levels, first to 3 correct).
- Data attribution: Open Trivia Database (CC BY-SA 4.0), OEIS (CC BY-SA 4.0), VisualPuzzles (MIT), Natural Earth (public domain), flag-icons (MIT). Credits screen and README.
- My Stats' filter reads Online, vs Computer (the games played on this device while logged in: `localStats`, `localHistory`; the data keeps its old names) and All; every label for those games says "vs Computer", never "Local". Ratings and the leaderboard are off (RATINGS_ENABLED = false). Don't re-enable without being asked.

## Workflow
- When debugging a match issue, ask me for the exported match log (the admin's Match inspector → Export) if one isn't attached.
- Keep changes scoped to what's asked. Touch only the relevant game folders.
- Run `npm test` for the games you changed. Run simulations only when a prompt asks or when changing a game's balance.
- Don't stop for review unless the prompt asks. If something is ambiguous, pick the option most consistent with these rules and note it.
- Deploy once at the end, to staging: `npm run deploy:staging -- "message"`. Production only when I say "release" (`npm run release`).
- Finish with a short report: what changed, anything skipped or uncertain, and the staging URL (https://staging.tictacchaos.com; the production URL too after a release). Keep it under 10 lines.
