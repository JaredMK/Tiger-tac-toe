# Tic Tac Chaos: project notes

Tic-tac-toe where every square is a mini-game. Mobile-first web game on Firebase Hosting, with Firebase (Auth, Realtime Database, Cloud Functions) for online play.

## Environments (read first)
- **Staging**: https://staging.tictacchaos.com, its own Firebase project (`.firebaserc` alias `staging`), the `staging` branch. **Production**: https://tictacchaos.com (www redirects to it), the project `tic-tac-chaos` (alias `production`), the `main` branch. The old GitHub Pages address redirects to tictacchaos.com.
- **Always work and deploy on `staging`**: `npm run deploy:staging -- "message"` commits and pushes to `staging`; the Deploy workflow (`.github/workflows/deploy.yml`) runs the tests and deploys the site, functions and rules to staging. Report the staging URL (https://staging.tictacchaos.com) after every change.
- **Production only on "release"**: deploy to production only when I explicitly say "release". Then run `npm run release` (from a clean checkout at staging's tip): it runs the tests, checks staging's deploy of that commit passed, lists the commits, asks for confirmation (type `release`) and fast-forwards `main` to `staging`; the push to `main` deploys production. Never push to `main` any other way, never deploy to production by hand, never dispatch a production run.
- The page picks its Firebase project by address (`src/env.js`, `window.TTC_ENV`; only the production hostnames get production, every other address gets staging). Staging data never mixes with production: separate projects, separate keys (each GitHub environment's `FIREBASE_SERVICE_ACCOUNT`; `scripts/check-key.js` refuses another project's key).
- Staging is gated: noindex (meta tag and robots.txt, `scripts/build-site.js`), a "STAGING" badge, and only accounts on the allowlist get in (the admin page's Staging Access, `admin/staging/allow`; `functions/index.js` `stagingAccess` puts a `staging` claim on the account; staging's server calls refuse anyone without it, `functions/.env.staging`; staging's rules are production's with every grant gated, `scripts/staging-rules.js`, applied by the staging deploy only). Seeded by `scripts/seed-staging.js` (test accounts, the admin), never with production data.
- Security (the October 2026 review, Phase 1): every online match is the server's (above); game content is escaped in every view (`esc`) and a record is held to its shape (`core/records.js` `parseMatch`: `tests/ui/xss.test.mjs`, `tests/core/parse-match.test.js`); the site sends a CSP and the other security headers (`firebase.json`, `admin.html` never framed); `track` and `devlog` need a login (the page signs in anonymously first: `net/tracking.js`), are rate-limited per caller (`functions/index.js` `rateOk`, `rate/{minute}`), new devices are capped per day, and a match's log never grows past `LOG_CAP`; App Check (reCAPTCHA Enterprise: `src/env.js` `appCheckKey`, `connect.js` `appCheck`) is wired and off until the keys exist, enforced on the functions by `TTC_APPCHECK=enforce` in `functions/.env.<project>`; the alert keys move to Secret Manager (`defineSecret`, bound once `TTC_SECRETS=on` in `functions/.env.<project>`: `firebase functions:secrets:set TWILIO_SID TWILIO_TOKEN TWILIO_FROM RESEND_KEY EMAIL_FROM`; the deploy makes placeholders; `admin/secrets` is read only until then and never backed up); the trivia workflow takes its inputs through env and never writes `main` or `staging`; `firebase-tools` is pinned; Matter.js loads from the site first. F3 (the skill games' results): see the Online standing rule (`core/verify.js`, `FIND_MATCH_HOLD`).
- `npm run check:envs` shows what is live where (each site's `version.json` against `main` and `staging`). The staging deploy also prints it, with a check of the old GitHub Pages redirect (a report, never a failure).
- Launch reset (`.github/workflows/reset-production.yml`, `scripts/reset-production.js`): manual, production only, dry run by default, deletes only with `RESET-PRODUCTION` typed; backs the whole database up first (`gs://tic-tac-chaos-backups/backups/<time>Z.json.gz`, read back and checked), then deletes matches, history, match logs, stats and tracking and puts every record at 0-0-0; accounts, usernames, admin, config, releases, features, bots, meta, review stay. Undo: `restore-production.yml` (`scripts/restore-backup.js`, `list` or a backup's name plus `RESTORE-PRODUCTION`; it saves the database first). Never run either unasked.

## Architecture
Plain ES modules, no build step: Firebase Hosting serves the files as they are (`scripts/build-site.js` only copies them into `_site/`, stamps the version and, on staging, adds noindex).

- `index.html`: the shell (meta tags, `#app`, `src/ui/fonts.css`, `src/ui/styles.css`, `src/env.js` (the Firebase project by address, the staging badge), `src/main.js` as a module).
- `src/main.js`: the entry. Loads every game's `view.js` (by the registry), registers the listeners in a fixed order, renders the sounds, boots.
- `src/core/`: the engine, pure (no page, no clock, no `Math.random`; every random choice from an rng passed in). `board.js` main board, turn flow, win and draw; `match.js` setup and new matches; `minis.js` a square's mini-game through the registry; `timer.js` one deadline a turn, playback timings; `random.js` seeded randomness; `ai.js` the computer on the main board (three levels: Easy, Normal, Hard; `cpuMove(state, rng, style, opts)`, opts.level/clock/budget); `aiw.js` the levels and the Hard weights (`config/ai`, tuned by `npm run tune-ai`); `mc.js` Hard's square choice by Monte Carlo playouts; `chaos.js` Super Chaos (simultaneous rounds vs the computer, or a friend in a room); `scgame.js` a Super Chaos match from Find Match as the server runs it; `records.js` online match records (secrets kept apart); `games.js` release control; `config.js` tunable settings; `replay.js` a move's replay log (its shape and limits; the server keeps it on the move's entry); `tune.js` every game's settings (`config/tune/<type>`: `tuneLive(type)` when dealing a square, `tune(mini)` after; a square keeps its values in `mini.tune`); `stats.js` (also `topOpponents`/`oppTally`: a profile's Top opponents, from the server's `oppStats` tally), `verify.js` (what the server holds a phone's move to beyond the rules: no timeouts, runs and attempts as their inputs within the time, attention answers after Start and in time), `util.js`. `engine.js` gathers the engine's public names (the server and tests use it as `E`).
- `src/games/<game>/`: one folder per mini-game (50, including the retired Dice race and Hexapawn).
  - `rules.js`: pure logic, shared with the server. Hooks the core calls: `create`, `apply`, `publicView`, `randomMove`, `moveFlash`, `secret`, `hide`, `flashMs`; Super Chaos's `scCreate`, `scRound` (a draw both moves that round share), `scFork`, `scApply`, `scAfter`, `scMerge` where a game needs them.
  - `ai.js`: `needs` (moves still needed) and `best` (the computer's move; `ctx.level` 'easy' | 'normal' | 'hard' and `ctx.until`, the ms a Hard search may still spend, null for a fixed amount of work: Hard searches or plays by expected value there, Normal is never changed by it).
  - `meta.js`: `info` (name, hint), `category` (its label at the top of its "?" explainer, e.g. "More luck"), `EXPLAIN_KEYS` where the explainer fills a `{setting}` from the game's own config rather than `TUNE` (Risky Rolls' `{target}`, `ui/explainer.js` `fillTune`), `explainer` ({ name, play, win } for the "?"), `icon`, `release` ('admin' or 'released'), `superChaos` (dealt in Super Chaos), `scOnly` (never in a normal match) and `scExplainer` where its rules differ there, default settings (`*_DEFAULTS`), `TUNE` (its settings for the admin's Mini-game Settings: `{ k, label, def, min, max, step, group }`; `{k}` in an explainer shows the value).
  - `view.js`: `screen`, `miniature`, `moveText`, `sounds`, `actions` (its own `data-act` controls), `replay` (hooks for the shared replay: `input`, `synth`) where it keeps a draft, its drawing, animations and input.
  - A hook a game lacks falls back to the core's default. Five Letters and Hangman keep their word lists in `words.js`.
  - Five Letters: no offensive answers or guesses (`core/badwords.js` is the username profanity list, shared with `functions/badwords.js`; `BAD5` in `words.js`; a refused guess says "Not allowed" and costs nothing); each guessed row carries the guesser's mark. Bowling: a turn is one roll at a fresh rack, every pin down counts with no bonuses, the target is its `target` setting (`bowlTarget`); the score boxes beside the lane (one roll each: pins, running total) are drawn on the canvas (`drawFrames`), an empty first box for each player from the moment the square opens, and fill in once the recording has played; the 35 target is set in the database by `scripts/set-releases.js` (`TUNE_SETS`), default 35. Sea Battle's shot dots carry the firer's colour.
- `src/games/shared/`: what a family shares (runner, attention, finger, physics with `physics-sim.js` on Matter.js, cards, lines, placement). A game's `rules.js` re-exports the family's hooks. Pinball's tables live in `physics-sim.js` (`PIN_LAYOUTS`, the lower table, `pinTable`, `pinLayoutCheck`): a square deals a layout and seven of its spots (`pinball/rules.js` `pinDeal`), and `tests/games/pinball.test.js` holds every layout to the layout check (an overlap fails `npm test`, so the deploys).
- `src/games/index.js`: the registry, one line per game (rules, AI, meta) in menu order, retired games last. `TYPES`, `TEST_TYPES` (from `meta.release`), `OLD_TYPES` and `INFO` come from it. The core dispatches with `rulesOf(type).apply(...)`, `aiOf(type).best(...)`, `viewOf(type).screen(...)`.
- `src/ui/`: `app.js` (state, timings, shared helpers), `render.js`, `board.js`, `mini.js`, `turnbar.js`, `turns.js` (computer's turn, result card), `replay.js` (opponent replays: an opponent's logged inputs played through the view, the Skip button; this phone's inputs logged for its moves), `chaos.js` (Super Chaos's round clock, recap and the 2x replay pop-up), `clock.js`, `input.js` (click handler; game controls go to the view's `actions`), `think.js` + `ai.worker.js` (the Hard computer's move worked out in a worker within its budget), `screens/`, and the shared components: `attention.js`, `runner.js`, `finger.js` (frameworks), `physics.js` (helpers), `progress.js` (bars, tallies), `explainer.js` (the "?" pop-up), `cards.js`, `track.js`, `keyboard.js`, `art.js`, `fx.js`. `sandbox.js` is the admin's Test play (`?sandbox=<game>&cfg=…`: one mini-game with the editor's unsaved settings, nothing saved). `config.js` holds the storage key and switches (`RATINGS_ENABLED`). `debug.js` puts the page's names on `window` for the browser tests and the console.
- `src/audio/sound.js`: the single sound manager. `SND.ensure` checks the context before every sound; any tap silently resumes it (or replaces it in the same tap when it is still down, closed or its clock stopped); the "Tap to restore sound" chip shows only when a tap could not bring it back, until sound runs again; state changes go to the device and match logs (devlog `audio`).
- `src/net/`: `connect.js` (Firebase config, SDK, App Check, server time), `room.js` (friend rooms: the lobby, opened and joined through the server, the match the server runs for it, presence, playback of the opponent's moves), `chaos.js` (Super Chaos online: each step a request to the server, recaps), `moves.js` (every online move is a request to the server), `matchmaking.js` (Find Match, and the listeners every server-run match uses), `accounts.js`, `releases.js`, `reactions.js`, `tracking.js` (stats and device events: always a signed-in call, anonymously at least).
- Client and server share `rules.js`: `functions/index.js` requires `src/core/engine.js` (Node 22 loads ES modules with `require`). `scripts/sync-functions.js` copies `src/core` and `src/games` (no views) and `trivia.json` into `functions/` before every deploy (firebase.json predeploy) and every emulator run.
- Load-time rule: a module must not use another module's value while loading if the two import each other (only inside functions). Keys and switches read at load live in `ui/config.js` and `core/config.js`.
- Link previews: `index.html` carries the Open Graph and Twitter tags (production's address); the image (1200x630), the 180x180 home-screen icon and the favicons are `assets/share/*`, drawn by `npm run share-images` (`scripts/make-share-images.js`: the game's fonts, colours and X and O characters) and copied in by `scripts/build-site.js`, which also points the tags at staging on the staging build. A `?room=` link previews like the home page (a rewrite cannot match a query string). `scripts/smoke-browser.js` checks the tags, the image and the icon on the live site after every deploy (`tests/server/share-preview.test.js` covers the build).
- Brand: `assets/brand/jarhad-labs-logo.svg` is the studio logo (the source of truth with `jarhad-labs-logo.png`); the main menu's credit inlines it without its background (`ui/screens/menu.js` `JARHEAD_LOGO`).
- `admin.html` + `playtest.js`: the admin dashboard: a menu of section tiles, each a page (`#overview`, `#players`, `#playtest`, `#matches`, `#settings` and `#settings/<type>`, `#bots`, `#releases`, `#stats`; on staging also `#access`, the allowlist). Mini-game Settings reads each game's `meta.js` (`TUNE`) and `core/tune.js` by import; the older tuning cards keep their own copies of a few defaults (`tests/core/admin-sync.test.js` checks them).
- Match logs (`functions/matchLogRules.js`): every online and Super Chaos match keeps a compact event log (`matchLogs/{key}`, summary in `matchLogIndex`), written by the server where it can (Find Match moves, the friend rooms' record, presence) and by the phone through `devlog` (`error`, `mlog`, `report`: `net/tracking.js`); deleted 30 days after the last event. The admin's Match inspector lists them (reported first), shows a timeline and exports one as JSON. The in-game menu's "Report a problem" (`ui/report.js`) flags the match.
- The computer: `scripts/ai-arena.js` plays the computer against itself over worker threads (`npm run tune-ai` tunes Hard's weights by self-play and saves them to `config/ai` with `--save`; never run automatically; `npm run sim -- levels` reports Hard against Normal). The bots' level is the admin's (`admin/config/bots/level`, Bot Settings).
- Tests: `npm test` runs `tests/games/<game>.test.js`, `tests/shared/`, `tests/core/`, `tests/server/` and `tests/page.test.js` (about 10 s); one game alone: `node --test tests/games/<game>.test.js`. `npm run sim -- <name>` runs a slow simulation in `tests/sim/` (`npm run sim` lists them). `npm run test:emulators` runs the server on the Firebase Emulator Suite (needs Java). `tests/server/room-rules.test.js` (in `npm test`) probes the friend rooms' security rules with SDK clients on the database emulator (the jar in firebase-tools' cache, `firebase setup:emulators:database`; skipped, and says so, without it or Java); `tests/ui/*.test.mjs` render page modules in Node with the browser's names stubbed.
- Help text: `docs/help-text.md` holds every player-facing help text (How to Play rules, the mode explainers, each game's explainer, credits, staging notices). `npm run export:help` writes it from the sources; `npm run import:help` (`scripts/help-text.js`, `--dry` to preview) writes edits back into `meta.js`, `src/ui/explainer.js` and the other sources, reports every change, warns about unknown or missing IDs, and touches nothing else. A new explainer or notice goes into `scripts/help-text.js` too (`tests/core/help-text.test.js` checks the round trip). A pattern there names the code around its text and captures text only: one that reaches into code fails the export (`noCode`).
- Deploy: `npm run deploy:staging -- "message"` (staging) and `npm run release` (production, only on my "release"); see Environments. The Deploy workflow deploys only what changed since that environment's last successful deploy: the site (Firebase Hosting, built into `_site/` by `scripts/build-site.js`), the functions, the rules (tests first, then a live check, `scripts/smoke-live.js`). `DEPLOY_REMOTE` picks the remote (the live repository is Tiger-tac-toe). Release switches asked for in a prompt go in `scripts/set-releases.js` (a new set id; each deploy applies each once to that environment's `releases/`).

## Adding a mini-game
Create src/games/<name>/ with rules.js, view.js, ai.js and meta.js, and register it. Every game needs: its settings (`TUNE` in meta.js, every tunable value), an explainer (in the format below), AI with a Hard form where the game has choices (`best` reads `ctx.level === 'hard'` and keeps to `ctx.until`), a miniature for the main board, AI, what a timeout leaves of a move under way (no move is played for a player out of time: `timeoutClose` where a begun move must end), animations, sounds, stats tracking, a default release status of Admin only, a category in its meta.js (`category`: 'luck', 'skill' or 'brain': shown as "More luck" etc. at the top of its "?" explainer; the Mini-games checklist is one alphabetical list).

## Standing rules (apply to every change)
- Lists fit the screen: a game-history row is a block button holding a grid (`.hirow .hin`) whose columns all shrink, so its board snapshot, texts and badges stay inside the row at 360px.
- Every mini-game must fit the screen with no scrolling, at any phone size down to 360x640: size its controls (a number grid, a keyboard, a board) from the space available, never from fixed pixels, with status and result text in reserved space.
- Layout never shifts. Reserve fixed space for status, result text and buttons; no board moves when text appears or disappears. Text never overlaps: a move's result text (live or in a replay, normal and Super Chaos) goes in its game's reserved result area and never covers other text or the game's drawing; text that swaps in over time (`.tu`/`.tf`/`.tu2`) shows one line at a time.
- Animations and sounds fire exactly once, from the move event that caused them, never from rendering or re-rendering. The main board shows a claimed square only after its replay finishes.
- Claims only on the main board (every mode): a mini-game view shows its own winning moment, never an X/O claim, stamp or "square won" message; the square turns X or O with the stamp after zooming out. Super Chaos claims come after the round resolves, shown on the board a square at a time once both moves have been shown (the winner's label and stamp; a square both won: both marks clash, then it resets, no claim). A player's own move always plays out fully (its animation and result, e.g. the Roulette spin) right after they make it, before any waiting screen, opponent replay or recap: a result of their own progress is never put off to the round's end. Only a result that needs both moves (Mini Golf's shared shot, a Bump knock) is settled at the round's end (`scMerge` returns `resolve`, or `replay`) and played in its square first. Bump: the spin plays at once in the player's own square (the wheel, their own piece's hops; nothing knocked yet); the round's end settles the knocks (`scMerge` `resolve`): if both spun there, both pieces hop together from where the round began, with any bump, as that square's joint resolution (no separate opponent replay), and the board settles to its final positions; the other player's lone spin is their replay, then any knock. Both moving in one shared square of Candy Race, Snakes and Ladders or Treasure Hunt (`rules.js` `scJoint`, `core/chaos.js` after `scMerge`): the recap plays both moves together in the player's own square from where the round began (`ui/track.js` `trackRoundEnd`; both digs open together), with no separate opponent replay, and the square settles to both. Every joint replay (both players in one square: Mini Golf's shots, Bump, Candy Race, Snakes and Ladders, Treasure Hunt, Sniff, Roulette's shared spin, Standoff Grid) uses the standard replay frame like any opponent replay: the pop-up over the board, the banner ("Both moves — replay"), the opponent's colour border, a Skip after 2 seconds and tap anywhere to skip (`ui/chaos.js` `scJointFrame`, `scSkip`; `ui/mini.js`). Super Chaos against the computer has no round clock (`sc.deadline` stays unset; `ui/chaos.js`, `clock.js`, `turnbar.js` show one only online). On a shared board where the other player's move can change the outcome (Standoff Grid's collisions, Sea Battle's last parts), the mover's own screen never shows a win, a line or a sink: their move plays unjudged (`scApply`), and lines and wins are looked for only at the round's resolution, after both moves (and any collision block) apply, as with Roulette and Mini Golf (`scMerge`; `resolve` plays it in the square). The main board never shows anything of the opponent's move (a miniature's change, a claim, their last-played badge) until that move's replay has played (`scShown`: `recap.mine`). No main-board change before its replay, on every path (claims, resets and the new mini-game a reset deals, miniatures; online, server-run and vs the computer, a late join or a reload): a square both won shows its old game until its replay or joint resolution has played, then clashes and resets (`scShown` treats a recap not yet under way as its waiting stage, never as the settled board). No gap between waiting and replay: the opponent's replay is available as soon as their move's result is known (online, the waiting phone starts the recap at once; only the last mover's phone starts it after its own result, `recap.lead`), and the waiting band ("Waiting for [name]…", `board.js` `waitBand`) stays up until the replay is ready to play. A player waiting in their own square for the round's end (Mini Golf, any joint-resolution game) sees that same band over the game, not small text. After locking in, a player sees their own outcome before anything else (online and vs the computer): a result settled only at the round's end (Mini Golf's shots, Roulette's shared spin, a Bump knock, Standoff Grid, Sniff, any game whose result needs both moves) plays in their own square first (`core/chaos.js` `scRecapOrder`). Both in the same square: once both are in, the joint resolution plays there in the player's own view (both shots, the shared spin, both moves and any collision: `scMerge` `resolve` with `joint`), its result held, and that square gets no opponent replay. The opponent elsewhere: own outcome first, then the opponent's replay. Both in the same square of an individual-progress game (Risk Wheels, Blackjack, Higher/Lower: nothing settled jointly): no joint resolution, so each still sees the other's replay. The opponent's replay always plays from its start the first time a phone reaches it (a phone held up, frozen or out of sight rewinds the recap to it: `ui/chaos.js` `oppCatchUp`), never a moment of it; a replay that cannot play is logged to the match log (`devError('replay')`), never shown as an empty pop-up. A phone that joins a recap late (out of sight, the menu open, reopened) still plays its own outcome from its start.
- Opponent moves (computer or online) are shown: highlight the square on the main board, zoom in, play the move with normal animation at human-like pacing, return. Real-time games show the opponent's attempt live. What a replay animates (the wheel's stop, the die's face, the words of a spin or roll) comes from the move being replayed, its recorded flash (`a` in a view's `screen`), never from the square's `mini.last`, which may be the viewer's own result (`tests/ui/replay-result.test.mjs`). A number a move changes (a Bank button's points, a score) keeps its old value until the move's animation lands and takes the new one then, timed from the move event (`.cnt` with a `data-delay`), never at the render.
- Every game must record and replay opponent moves through the shared replay system (`core/replay.js`, `ui/replay.js`): a move carries a compact log (its inputs with their timings, or the run's/attempt's own log or recording) that plays back deterministically through the game's normal view: the selection pressed and typed in, then the move. Online the log rides the move; the computer's moves get one too. Replays play at normal speed with a Skip button after 2 seconds; every replay (all games, all modes, the Super Chaos pop-up too) plays through to the end of the move, every animation of it finished, and holds the final state, the score updated, for about 1 second before it closes (a game's `flashMs` covers all its move's animations; the hold comes after); Super Chaos replays the computer's round at 2x in a pop-up over its square (idle gaps over 0.3 s cut to 0.3 s, a "[name]'s move — replay" banner, a frame in its colour, a replay icon, tap anywhere to skip; Mini Golf's shared shot is the reference), and the board badges each player's last-played square. A game whose view plays the mover's screen from the flash itself (a run, an attempt, a reveal, a throw) says so (`OWN` in `ui/replay.js`); one with a draft (letters, pegs, numbers, cards, a two-tap aim, a pull) adds `replay` hooks (`input`, `synth`) in its `view.js`.
- No help text inside mini-games. Instructions live only in the "?" explainer: "Name — Play: … Win: …", plain and short.
- Sound: one AudioContext, resumed on every tap and whenever the page becomes visible. Game inputs play only their own sound, never the UI click. CC0 or synthesised sounds only, listed in SOUNDS.md.
- Mobile: touch-action none on play areas; no long-press magnifier, selection or callout; no tap highlight; no horizontal scrolling; aim for 60fps. Inputs can start anywhere on the mini-game screen.
- Original art only. No characters, logos or names from existing games or brands. Colours and fonts come from the shared style tokens.
- Online: every online match is server-authoritative, Find Match's and a friend room's alike (`games/{id}`: `pub` for the players, `sec` for the server alone; `functions/index.js` `changeGame`/`changeSc`). A friend room is only a lobby on the database (`rooms/{code}`: host, seats, setup, status, `game`, rematch flags, `left`), opened and joined through the server (`openRoom`, `joinRoom`: a fresh code, the free seat; no room is ever listed or read before one is seated in it), started by the host (`startRoom`, also the rematch once both flags are in) as a `games/{id}` match. The host is Player 1 and the friend Player 2 in the lobby (no X/O choice), and X and O are drawn at random by `startRoom` for every match, the rematch too (`drawSeats`; `setup.hostPick` always 'random'; only the emulator's tests may keep the host on X, `TEST_SEATS`). The invite (`net/room.js` `shareRoom`, `inviteText`) carries the code in its words and its link ("Join my Tic Tac Chaos game! Code: ABCDE tictacchaos.com/?room=ABCDE"); the Join screen takes the code, and the link joins at once (`main.js` `autoJoin`, the name kept from before, else "Friend"). The match carries `mode: 'friend'` and `pub.room`; the phones then use the Find Match path (`state.online.kind === 'mm'` with `room`; `net/room.js` `enterRoomGame`, `lobby`), the records are credited as friend games by `finishGame` (players with a username only; a guest without an account gets no record or history), a forfeit closes the room (`status: 'over'`), the sweep deletes rooms a day old. The rules let a player write only their own seat's name, the host the setup in the lobby, each their rematch flag (`rematch/{side}`, server time) and their leaving (`left`, once); only the two players read the room or its presence (`presence/{code}`, `gpresence/{id}`: shape-checked). No phone ever writes a match record (security review F1/F4/F5/F10/F12; `tests/server/room-rules.test.js`). Hidden information (answers, decks, hidden cells) stays on the server until revealed. Physics games: the client sends aim and power, the server simulates and sends a recording, both phones replay it. Real-time skill games send their inputs, and the server works the result out itself (security review F3; `core/verify.js` `onlineCheck`, the one set of checks for Classic `move` and Super Chaos `applyScMove`): a run is its input log, played through again step for step (`runner.js` `runCheck`; a run without its log is refused) and no longer than the turn or round has lasted (`RUN.clockSlackMs`; `sc.began`); Sky Hop and Scoop Stack attempts are their inputs, played through again (`finger.js` `fingCheck`); a Pinball ball is its inputs too (`w.log`: the flippers as they change, each launch and its power, at their steps; `physics-sim.js` `pinReplay`), re-simulated on the server, which keeps its own ball's result and recording (`pinball/rules.js` `pinReplayCheck`; the phone's claim only noted as `last.diff`; local play still sends the recording, `pinCheck`); every attempt comes after Start (`attStart` stamps `mini.started[p]`, server time: Classic `move` kind `start`, Super Chaos `scStart`/`applyScStart`; the phone waits for the answer, `net/moves.js` `dbStart`) and lasts no longer than the time since; an attention game's round is the server's until Start (`attention.js` `attentionHide`: the public state shows its frame alone, `attFrame`; the rounds ride the secrets; Start hands the round over, `r.round`) and its answer must come within the round's time plus `ATT.answerMs` (else it counts as out of time). Find Match deals only games the server can verify so (`core/games.js` `FIND_MATCH_HOLD`, cut from Find Match's games in `makeGame`, never from friend rooms or local play): Bullseye stays held, since a throw is where two lines sweeping about once a second were stopped and the server cannot time a tap to better than a connection's slack.
- Leaving and rematches: a match left through the menu ends as a loss on the record (friend rooms `net/room.js` `leaveMatch`/`tellLeft`, Find Match `resignMM`, a logged-in local match `resignLocal`), and both phones stay for the result first: the leaver sees the loss screen, the other the win screen ("[name] left the match"), then Main menu. A friend room marked `left` offers no rematch. A friend-room rematch needs both players: a tap sets `rooms/{code}/rematch/{side}`; the other phone shows "[name] wants a rematch" in a bubble under its buttons (`ui/screens/win.js` `rematchNote`), the requester "Waiting for [name]…" with Cancel (`rematchCancel`); with both flags in, either phone starts the match (`rematchStart`, a transaction that clears the flags). Top opponents (`oppStats`) count finished online matches against opponents with a registered username, in every mode (`functions/index.js` `friendGameDone`, `finishGame`); guests and accounts without a username never count.
- Release control: new games default to Admin only. Admin-only games never appear to non-admins anywhere, and never in Find Match.
- Classic only, everywhere: Super Chaos is off for everyone, admins included (`core/config.js` `SUPER_CHAOS_ENABLED` false, read by the page and the server; `releases/superchaos` set off by `scripts/set-releases.js` `rel2`; the admin's Releases page says so). No mode selector or mention anywhere: menus, Same phone, the host's room, the join screen, Find Match, How to Play (no Modes section), explainers. Its code and settings stay for when it returns (`core/chaos.js`, `scgame.js`, `ui/chaos.js`, `net/chaos.js`, each game's Super Chaos hooks and `scExplainer`, the `QUEUES.chaos` queue): the server opens the Super Chaos queue and a room's switch only in the emulator, for its tests (`functions/index.js` `SC_OK`). With the switch back on, the Mode selector (`net/releases.js` `scPicked`/`scMode`/`setMode`; `ui/screens/setup.js` `modeRow`) and the Super Chaos rules in these notes apply again.
- Main menu: Play Computer, Play a Friend, Find Match, then How to Play; login, stats (your username), sound and the admin entry as before. Play Computer starts a Classic match at once, no setup screen: the player's side drawn at random, every released game (not the admin-only ones, even for the admin), Normal (`core/match.js` `startQuick`, `state.quick`: its rematch is another, the side drawn again); the player's username, or "You". Play a Friend: Host game, Join game and a small Same phone (two people on one phone: the setup with names, player 1's side X, O or Random, and the mini-games; no computer). Find Match greyed ("Not available at this time") while the admin has it off; "Back to your match" while one is under way. (There is no Play Local or Play Online screen any more.)
- Side reveal: every match opens with the same "You are X" / "You are O" card (`net/matchmaking.js` `showSides`, `showIntro`; `ui/screens/find.js` `renderIntro`): Find Match (with the records), a friend room's match and each rematch (`o.introFor`), Play Computer and Same phone (who is which: "Player 1 is X · Player 2 is O" when no names). About 3 seconds or a tap; the computer waits for it (`ui/turns.js` `scheduleCpu`, `onIntroClosed`); online, the server's first-turn grace covers it.
- A fresh visit (any page load) opens the main menu: no other screen is restored from the saved state (`net/matchmaking.js` `freshVisit`, called by `main.js` boot). The exceptions: a join link (`?room=`) goes to joining; an online match still in progress is held (`holdResume`, kept on the device) for the menu's "Resume match" button (`resumeMatch`: back in from the server's record), never entered by itself, and the button goes once that match is over (`checkResume`). A lobby left behind lets go of its seat. Find Match is Classic, run by the server (`serverRules.js` `QUEUES.match`: 60 s a turn; `functions/index.js` `findMatch` (every page gets this queue, `queueKey`), `changeGame`, `move`/`timeout`), with a bot for a lone searcher once their wait is over (`planBot`/`runBot` at the admin's level, counted apart). The Super Chaos queue (`QUEUES.chaos`: `core/scgame.js`, `changeSc`, `scMove`, `scTick`, `scBegin`, `net/chaos.js` `scRequest`, `planScBot`/`runScBot`) stays as code, reachable only by the tests while Super Chaos is off. Ranked, when it comes, is these matches.
- Turn timer: one deadline per turn, never reset by actions within a turn. It starts only once the replays before it are over: in Classic, when the player on the move has finished or skipped the replay of the previous move (their phone starts it on the record, `core/timer.js` `startClock`; at the latest when that replay would have ended, `startBy`); in Super Chaos, the next round's clock starts only when both players have finished or skipped the recap and its replays (`sc.ready`, `applyChaosBegin`/`applyScBegin`; a bot is through at once, a phone gone is waited for `SC_ONLINE.readyWaitMs`).
- Timeouts (all modes): no automatic move, random or otherwise. No phone ever plays a timeout: `'auto'` sent from a phone is refused online (`core/verify.js` `AUTO_FROM_PHONE`; Odd One Out's own pick timer is the one exception, and it only counts against the sender); a timeout move is the server's, from the deadline. A missed turn (or Super Chaos round) does nothing: the turn passes, the round goes on without that player's move. A move already under way ends as it stands (`timeoutClose`: Risky Rolls banks, Blackjack stands, a round or attempt begun fails; a bonus move owed is not taken), which is not a miss. Two consecutive misses by the same player means they surrender and lose the match (`winReason` 'timeout'). Misses are enforced by the server whether or not either phone is open (being away never pauses a turn or round): every online match (Find Match and friend rooms alike) by `games/{id}/dl`, the deadline sweep each minute, the phones' `timeout`/`scTick` calls and a bot's Cloud Task. A forfeit is recorded (stats, history), closes a friend room (`status: 'over'`, no rematch) and shows "[name] forfeited — 2 missed turns" to both phones when they return. The record is the one truth: a phone waiting on the other side asks the server every few seconds (`scTick`, `scBegin`, `tick`), so a dead connection never holds a round. (`core/records.js` still holds the record-transaction engine of the old friend rooms, `applyChaosSubmit`/`applyRoomSweep`/`scResyncPlan`, used by the tests only.)
- Stats count only squares that ended claimed by X or O, and none from abandoned matches (resigned, lost on time, never finished). Bot games are tracked separately; Super Chaos squares (computer and friend rooms) under `chaos`. Match averages cover finished matches only.
- Balance targets: about 4–6 of a player's own moves to win a square; no guaranteed wins in 2 moves; every move should help the mover more than the opponent (no waiting traps); first-mover win rate under 60%. Tunable values live in the admin config, not in code: a new tunable goes in the game's `TUNE` (Mini-game Settings).
- Shared components: quiz games (Trivia, Patterns, Geo Quiz) use the quiz component (Reveal locks the player in, cross-outs centred and shared, question persists until solved, button press feedback). Runners use the runner framework. Attention games use the attention framework (Start locks the player in, 3 levels, first to 3 correct).

## Workflow
- When debugging a match issue, ask me for the exported match log (the admin's Match inspector → Export) if one isn't attached.
- Keep changes scoped to what's asked. Touch only the relevant game folders.
- Run `npm test` for the games you changed. Run simulations only when a prompt asks or when changing a game's balance.
- Don't stop for review unless the prompt asks. If something is ambiguous, pick the option most consistent with these rules and note it.
- Deploy once at the end, to staging: `npm run deploy:staging -- "message"`. Production only when I say "release" (`npm run release`).
- Finish with a short report: what changed, anything skipped or uncertain, and the staging URL (https://staging.tictacchaos.com; the production URL too after a release). Keep it under 10 lines.
